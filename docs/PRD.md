## 一、产品背景与定位

### 1.1 一句话定位

**用户想问冷知识、想验证流言真假，系统用多 Agent 协作查证、讲得有趣，并且——辟谣时不止说"这是假的"，还追溯"误解从哪来、为什么流传"。**

### 1.2 需求背景

人对世界有两种好奇：一是「想知道新奇的事」（冷知识），二是「想验证听说的事是真是假」（辟谣）。现有获取方式都有痛点：

| 现有方式 | 痛点 |
|---------|------|
| 搜索引擎 | 结果杂乱、广告多，真假要用户自己筛 |
| 短视频科普 | 被动接收、无法主动提问、来源不明 |
| 维基百科 | 硬核、不够有趣、英文多 |
| 口口相传的"常识" | 大量误解流传（鱼 7 秒记忆、左脑理性），真假难辨 |

### 1.3 为什么用 AI（而非传统方案）

| 方案 | 问题 |
|------|------|
| 传统搜索引擎 | 返回一堆链接，用户自己判断真假 |
| 人工整理的知识库 | 内容固定，用户想问的不一定有 |
| **多 Agent AI 探索机（本方案）** | 用户随便问，AI 检索 + 科普/辟谣 + 溯源 + 审查，给出**有据可查**的答案 |

**核心价值**：不是"我告诉你几条冷知识"，而是"你想知道什么、想验证什么，我帮你查证、讲得有趣、还告诉你误解从哪来"。

### 1.4 产品定位：一体两面

```
功能 A：冷知识探索（猎奇）——"章鱼有几个心脏？" → 有趣的答案
功能 B：误解辟谣（去伪）——"鱼记忆只有 7 秒？" → 真相 + 误解溯源

一体两面：探索未知（增长见识）＋ 破除误解（纠正认知）
```

## 四、产品决策权衡（面试可讲）

> 本章记录几个"看起来是技术选择、实则是产品权衡"的决策，是本 PRD 的核心。

### 决策 1：为什么用多 Agent，而不是一个 Prompt 问到底？

- 把"查证 → 判断真假 → 追溯误解 → 标注来源 → 推荐延伸"拆成 **7 个职责单一的 Agent**，每个 Prompt 聚焦一件事。
- 收益：某个环节出问题可**单独优化或替换**（如单独升级辟谣 Agent）；路由按问题类型**动态编排链路**，冷知识和辟谣走不同路径，不做无用功。

### 决策 2：为什么「知识库优先 + LLM 兜底」，而不是纯 LLM？

- 每个 Agent 都是双通道：**命中本地知识库 → 直接用整理好的结构化字段**（质量最高、零延迟）；**未命中 → 调 LLM 现场生成**。
- 这体现 RAG 的核心思想：**不预存全部知识，而是需要时检索**。冷知识海量、每天更新，人工填不全也填不完；本地只存高质量精选（当前 209 条），长尾靠联网检索兜底、仍不足则拒答。

### 决策 3：联网检索 —— 从"不做"到"做了但要守住边界"（v1 决策 + v2 修订）

**v1 的判断（MVP）**：
- 联网检索需要额外插件/API 成本，且来源质量不可控——抓回来的网页可能本身就是谣言的源头。
- 所以 MVP 选择：知识库未命中时让 LLM 基于公认常识生成，同时**强制 SourceAgent 标注"AI 综合分析 · 无本地权威来源，建议核实"、ReviewAgent 标注 🟡**。
- **产品底线**：宁可用"诚实标注的 AI 分析"覆盖长尾，也不假装有权威来源。

**v2 的修订（实现联网后发现原判断只对了一半）**：
- 原判断成立的部分：**搜索结果确实不能当权威**。所以联网路径**永远不下真/假结论**（`verdict` 恒为 None），只陈述搜到的事实并标 `[1][2]`。
- 原判断不成立的部分：长尾问题靠 LLM 凭记忆答，用户完全无法核实；而"给出来源链接让用户自己点开看"反而比"AI 综合分析"更诚实。
- 因此改为**三级证据来源**：
  1. **本地知识库命中** → 可给真/假结论（人工整理、有 verdict 字段）；
  2. **本地未命中 → 联网检索**（PubMed 论文库优先，其次 Bing/360/搜狗/百度）→ **不给结论**，只给带编号的搜索结果；有学术/权威域名标 🟢，否则标 🟡"无法确认来源"；
  3. **联网也搜不到** → 诚实拒答。
- **两条防火墙**（这是新增的关键设计，见第七章）：
  - **相关性闸门**：搜索结果标题/摘要里连查询词都不出现就丢弃。曾出现"搜公司名返回旅游攻略、却因域名是 gov.cn 被判为权威来源"的荒唐情况，就是靠这道闸门修的。
  - **搜索结果不足即降级**：回答开头或结尾出现"无法确认/不足以/未找到"时，直接按拒答处理，避免出现"回答里说不知道、状态却显示成功"的矛盾。
- **结论**：不是推翻原决策，而是把它精确化为"**可以检索，但检索结果不等于结论**"。

### 决策 4：为什么辟谣要做「误解双重溯源」？（核心差异化）

- 只说"这是假的"价值有限——用户知道了结果，下次遇到类似的还是不会判断。
- **溯源误解**（从哪来 + 为什么流传）帮用户建立批判思维，是普通辟谣和本产品的分水岭。
- 同时严守诚实原则：起源明确的标注来源，模糊的说"待考证"，完全查不到的说"起源不明"——**不编造起源**。

### 决策 5：为什么「三级置信度 + 诚实拒答」，而不是"尽量给答案"？

- 冷知识娱乐属性强，但**辟谣把对的当假的辟出去，危害比不辟谣更大**。
- 用三级置信度分级处理不确定性：有权威来源正常答，非权威标"趣味参考"，无可靠来源**诚实拒答**。

## 五、指标体系

### 5.1 北极星指标

**回答有据可查率** = 带来源/置信度标注、且标注准确的回答占比。

> 选它而非"提问量"的理由：本产品的核心价值是"靠谱"，不是"能聊"。提问量高但答案不可信，对这个品类是负资产。

### 5.2 支撑指标（量化目标）

| 指标 | 定义 | 目标值 |
|------|------|--------|
| 有来源标注的回答占比 | 回答带 source 字段的比例 | ≥ 80% |
| 诚实拒答率 | 无法验证时正确拒答（不编造）的比例 | ≥ 90% |
| 辟谣溯源命中率 | 辟谣类问题给出误解溯源的比例 | ≥ 60% |
| 响应时间 | 从提问到出答案的端到端时间 | P95 < 5 秒 |
| 留存 | 单次会话平均提问数 | ≥ 3 次 |

## 六、技术方案（与代码对齐）

### 6.1 多 Agent 架构

```
用户提问："鱼的记忆只有 7 秒？"
                    │
        ┌───────────▼───────────┐
        │  Orchestrator（总调度） │  判类型：冷知识 / 辟谣（1 次轻量 LLM）
        └───────────┬───────────┘
        ┌───────────┴────────────┐
   冷知识链路                  辟谣链路
        │                         │
  检索→科普→溯源→延伸        检索→辟谣→误解溯源→溯源→延伸
        └───────────┬────────────┘
        ┌───────────▼───────────┐
        │   审查 Agent（置信度）  │  三级置信度，防幻觉兜底
        └───────────┬───────────┘
  答案 + 真相溯源 + 误解溯源 + 相关推荐 + 置信度
```

### 6.2 七个 Agent 职责

| # | Agent | 职责 | 冷知识链路 | 辟谣链路 |
|---|-------|------|:---:|:---:|
| 1 | 检索 Agent | 本地 RAG 检索相关资料（零 LLM） | ✅ | ✅ |
| 2 | 科普 Agent | 资料 → 有趣易懂的科普答案 | ✅ | — |
| 3 | 辟谣 Agent | 判断真假，返回 `verdict/answer/truth` | — | ✅ |
| 4 | 误解溯源 Agent | 追溯误解起源与传播原因（**亮点**） | — | ✅ |
| 5 | 溯源 Agent | 标注信息来源（零 LLM） | ✅ | ✅ |
| 6 | 延伸 Agent | 生成"你可能还想知道" | ✅ | ✅ |
| 7 | 审查 Agent | 评估置信度，防幻觉（零 LLM） | ✅ | ✅ |

> 注 1：早期设计中有一个独立的"翻译 Agent"，落地时并入科普/辟谣的 Prompt（当前知识库以中文为主），
> 故核心链路为 7 个 Agent。
>
> 注 2：v2 在此基础上新增了 3 个 Agent 和 1 个核查器：`IntentAgent`（判"求证/求知"）、
> `QueryRewriteAgent`（生成中英文检索式）、`WebAnswerAgent`（只按搜索结果作答，不下结论），
> 以及 `GroundingVerifier`（生成后逐句核查支撑率）。当前代码共 **10 个 Agent 类 + 1 个核查器 + 1 个编排器**。

### 6.3 RAG 检索实现

轻量级实现，**刻意不用向量数据库**：
- 中文按字分词 + 英文单词整体 token，剔除高频停用词；
- 标题命中 ×3 权重 + 正文命中 ×1 打分，取 Top-3；
- 相关性门槛：命中标题实义词，或正文覆盖过半查询关键词，避免"的/吗"这类功能词误命中。

### 6.4 可插拔大模型

| 模式 | 说明 |
|------|------|
| mock（默认） | 无 Key 开箱即跑，返回结构化占位，便于演示 |
| MiniMax / DeepSeek | 填 Key 即切换，兼容 OpenAI 格式，一行配置换模型 |

### 6.5 响应数据结构

```json
{
  "route": "debunk",            // knowledge | debunk
  "verdict": "fake",            // true | fake | partial | null
  "answer": "鱼的记忆可达数月……",
  "truth": "鱼的记忆可达数月甚至更长",
  "origin": "被《海底总动员》多莉角色强化传播",
  "why": "简单有趣的说法更易传播",
  "source": "维基百科 · 动物行为学研究",
  "confidence": "high",
  "confidence_label": "🟢 确证 · 有权威来源",
  "related": ["🐙 章鱼有 3 个心脏和蓝色血液", "..."],
  "materials_hit": 1
}
```

## 七、防幻觉设计（核心竞争力）

### 7.1 三级置信度机制

| 等级 | 条件 | 展示 |
|------|------|------|
| 🟢 确证 | 命中本地权威来源 | 正常回答 + 来源标注 |
| 🟡 趣味参考 / AI 分析 | 有来源但非权威，或 LLM 兜底生成 | 回答 + "建议核实" |
| 🔴 存疑 | 无资料且无模型（mock） | 诚实提示"暂时没找到可靠资料" |

### 7.2 防幻觉三道防线

```
防线 1：强制基于检索 —— 检索 Agent 优先本地库，未命中才 LLM 兜底
防线 2：置信度标注 —— 审查 Agent 让用户知道结论有多可靠
防线 3：诚实拒答 —— 无可靠来源时不强行给答案、不编造
```

### 7.3 真实踩坑：检索误命中（单字分词的坑）

**现象**：问"为什么天空是蓝色的"这类知识库外的问题，系统却返回了知识库里"人的血液是蓝色的"的答案——答非所问，且置信度错误标成 🟢 确证。

**根因**：检索最初用单字（unigram）分词，把"蓝色"拆成「蓝」「色」两个独立字，和"血液是蓝色"里的两个字错误对齐，造成误命中。

**影响链**：误命中 → `top` 非空 → 被当作"命中高质量条目" → 返回库内答案 + 误标高置信度。这直接破坏了防线 1（强制基于检索）——检索给的"证据"本身是错的，后面全错。

**修复**：改用二元组（bigram）分词，过滤含功能字的跨词垃圾组合，命中门槛从"标题命中 1 字"提高到"标题命中 ≥2 个独立实义词"。

**验证**：真实命中（"章鱼有几个心脏"）保留，误命中（"天空是蓝色"→"血液是蓝色"）归零；知识库外问题正确走 LLM 兜底并标 🟡。

**产品启示**：防幻觉的第一道防线是**检索质量**——如果检索把无关内容当证据喂给模型，再好的 Prompt 约束也兜不住。排查问题要按「数据 → 检索 → 生成」分段归因，而不是一上来就怪模型。

## 十一、范围外 / 风险 / 里程碑

### 11.1 范围外（本期不做）
- ❌ 用户账号系统（无需登录）
- ❌ 收藏 / 分享功能
- ❌ 多轮深度对话（当前为单轮问答 + 推荐）
- ❌ 社区 / UGC

**已从"范围外"移入已实现（v2）**：
- ✅ 联网检索（PubMed + 多引擎，带相关性闸门与权威域名判定）
- ✅ 生成后核查（GroundingVerifier，支撑率低于阈值改判拒答）
- ✅ 意图分层（IntentAgent，区分求证与求知）
- ✅ 离线可复现评测（`backend/evaluate.py`，种子固定、结果落盘）

### 11.2 风险与缓解

| 风险 | 缓解 |
|------|------|
| 知识库覆盖有限 | 联网检索兜底；仍不足则诚实拒答 |
| 搜索结果可能不权威 | 联网路径不下真/假结论；只有学术/权威域名才标高置信度 |
| 联网结果跑偏 | 相关性闸门（标题/摘要必须命中查询词）+ 来源不足即降级为拒答 |
| 误解起源难溯源 | 诚实标"待考证"，不编造 |
| 幻觉风险 | 审查 Agent + 三级置信度 + 拒答 |

### 11.3 里程碑
- **✅ MVP（v1）**：7 Agent 协作 + 本地 RAG + 三级置信度 + mock/MiniMax/DeepSeek 可插拔 + 自建前端。
- **✅ v2（已完成）**：意图分层（IntentAgent）+ 联网兜底（PubMed/Bing/360/搜狗/百度 + 相关性闸门）
  + 查询改写（中英双语检索式）+ 生成后核查（GroundingVerifier）+ 可复现评测（15 题，7 项指标）
  + 路由重排与辟谣证据过滤。
- **⬜ v2.1（计划）**：评测集扩到 100+ 题并人工校准标准答案；流式输出；翻译 Agent 拆分。
- **⬜ v3.0（远期）**：多轮对话、用户收藏、每日主题轮换。
