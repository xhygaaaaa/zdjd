## 一、背景与目标

### 1.1 需求背景
人对世界有两种好奇:一是"想知道新奇的事"(冷知识),二是"想验证听说的事是真是假"(辟谣)。现有获取方式有痛点:

| 现有方式 | 痛点 |
|---------|------|
| 百度搜索 | 结果杂乱、广告多、真假难辨 |
| 短视频科普 | 被动接收、无法主动提问、来源不明 |
| 维基百科 | 内容硬核、不够有趣、英文内容多 |
| 各种"常识" | 大量误解流传(鱼7秒记忆、左脑理性),不知真假 |

### 1.2 产品定位:一体两面
```
功能A:冷知识探索(猎奇)——"章鱼有几个心脏?" → 有趣的答案
功能B:误解辟谣(去伪)——"鱼记忆只有7秒?" → 真相 + 误解溯源

两个功能一体两面:探索未知(增长见识)+ 破除误解(纠正认知)
```

### 1.3 为什么用AI(而非传统方式)
| 方案 | 问题 |
|------|------|
| 传统搜索引擎 | 返回一堆链接,用户要自己筛选、判断真假 |
| 人工整理的冷知识库 | 内容固定,用户想问的不一定有 |
| **多Agent AI探索机(本方案)** | 用户随便问,AI检索+翻译+科普+溯源+辟谣,给出有据可查的答案 |

**核心价值**:不是"我告诉你几条冷知识",而是"你想知道什么、想验证什么,我帮你查证、讲得有趣、还告诉你误解从哪来"。

### 1.4 产品目标(量化)
| 目标 | 指标 | 目标值 |
|------|------|--------|
| 回答有据可查 | 有来源标注的回答占比 | ≥ 80% |
| 内容有趣 | 用户点赞率 | ≥ 70% |
| 防止幻觉 | 无法验证时正确拒答率 | ≥ 90% |
| 辟谣价值 | 误解类问题给出溯源的占比 | ≥ 60% |
| 体验流畅 | 响应时间 | P95 < 5秒 |
| 用户留存 | 单次会话平均提问数 | ≥ 3次 |

## 三、回答模式定义(AI产品特有)

| 模式 | 触发条件 | 技术路线 | 说明 |
|------|---------|---------|------|
| 冷知识问答 | 用户问新奇事实 | RAG检索+科普 | 有趣的知识 |
| 误解辟谣 | 用户问"XX是真的吗" | RAG+真相溯源+误解溯源 | 辟谣+溯源 |
| 联网检索 | 知识库未命中 | 联网搜索+多Agent | 覆盖长尾 |
| 拒答模式 | 检索不到可靠依据 | 返回诚实提示 | 防止编造 |

> 设计理由:冷知识和误解都海量,不可能预置全部。核心不是"什么都能答",而是"能查+有据+诚实"。查不到的老实说,不瞎编。

## 四、知识库策略:实时联网 + 主题轮换(重点)

### 4.1 为什么不预存全部知识?
```
❌ 想法:把所有冷知识存进知识库
   问题:冷知识海量、每天更新,人工填不全也填不完

✅ 方案:知识库不追求"全",而是"精选 + 实时补充 + 主题轮换"
```

### 4.2 三层知识获取机制

```
用户提问
    ↓
① 本地精选知识库(你手动整理的高质量50-100条)
   ├─ 命中 → 用(质量最高)
   └─ 没命中 ↓
② 实时联网检索(维基/百科/科普网站)
   → 覆盖你没预存的长尾问题,内容永远最新
   └─ 查不到 ↓
③ 拒答(诚实说"暂无可靠资料")
```

**核心思想**:靠实时联网解决"知识库不全"和"内容更新"问题,不依赖人工每天维护知识库。

### 4.3 主题轮换(制造每日新鲜感)

系统预设"主题日历",每天首页"今日主题"轮换:

| 星期 | 主题 | 图标 |
|------|------|------|
| 周一 | 海洋动物 | 🐙 |
| 周二 | 宇宙天文 | 🌌 |
| 周三 | 人体奥秘 | 🧠 |
| 周四 | 植物世界 | 🌱 |
| 周五 | 历史冷知识 | 🏛️ |
| 周六 | 食物真相 | 🍯 |
| 周日 | 经典误解辟谣 | 🔍 |

> 用户每天来都有新鲜主题,不需要知识库真的"自更新",靠主题轮换 + 实时联网制造新鲜感。

### 4.4 半自动更新(进阶,可选)
```
如果想让本地知识库增长(非必须):
- 定时任务每天从维基"每日精选"抓取热门词条
- 自动整理成新条目
- 但Coze免费版不一定支持定时任务,MVP阶段不做
```

### 4.5 面试金句
> "知识库不可能预存所有冷知识,也不可能靠人工每天更新。我的设计是'精选库+实时联网+主题轮换':本地存高质量精选,长尾问题实时联网检索(内容永远最新),再用今日主题轮换制造新鲜感。这体现了RAG的核心——不预存全部知识,而是需要时检索。"

## 五、多Agent架构设计(核心)

### 5.1 整体架构

```
用户提问:"鱼的记忆只有7秒?"
    ↓
┌─────────────────────────────────────┐
│  Orchestrator(总调度Agent)          │ 判断是冷知识还是辟谣,分配任务
└─────────────────────────────────────┘
    ↓
┌──────────┬──────────┬──────────┬──────────┬──────────┬──────────┐
│检索Agent │翻译Agent │科普Agent │辟谣Agent │延伸Agent │溯源Agent │
└──────────┴──────────┴──────────┴──────────┴──────────┴──────────┘
    ↓
┌─────────────────────────────────────┐
│  审查Agent(质量把关+置信度)         │
└─────────────────────────────────────┘
    ↓
输出:答案/辟谣 + 真相溯源 + 误解溯源 + "你可能还想知道"
```

### 5.2 各Agent职责与Prompt

#### Agent 1:检索Agent
**职责**:从知识库和联网搜索相关资料
```
你是信息检索专家。
用户问题:{用户输入}
请检索相关信息:1.优先本地知识库 2.无结果时联网搜索权威来源(维基、科普网站、学术资料)
输出:检索到的原始资料 + 每条来源。
检索不到可靠信息时,明确返回"未检索到相关资料"。
```

#### Agent 2:翻译Agent
**职责**:把英文资料(PubMed、英文维基)翻译成中文
```
你是专业中英翻译。
原始资料:{检索结果}
翻译成通俗易懂的中文,保留专业术语准确性。原文已是中文则直接透传。
```

#### Agent 3:科普Agent
**职责**:把资料转化成有趣、易懂的科普内容
```
你是擅长讲冷知识的科普达人。
资料:{翻译后资料} 用户问题:{用户输入}
用轻松有趣的语气回答:1.先给直接答案 2.再通俗解释为什么 3.语气活泼像朋友聊天 4.不超300字 5.只用资料中的信息,不编造。
```

#### Agent 4:辟谣Agent(处理误解类问题)★
**职责**:判断说法真假,给出真相
```
你是辟谣专家。
用户说法:{用户输入} 资料:{检索结果}
判断这个说法是:✅真 / ❌假 / 🔶部分正确
给出:1.明确结论 2.正确的事实是什么 3.基于资料,不臆断
如果资料不足以判断,说"暂时无法确认真伪"。
```
#### Agent 5:误解溯源Agent(处理误解的起源)★★★ 亮点
**职责**:分析误解怎么产生、如何传播
```
用户的说法经核实是误解:{用户输入}
请分析:
1. 这个误解最早可能从哪来(起源:某影视作品/假新闻/民间传说)
2. 为什么会广泛流传(传播原因)
3. 能找到起源就标注,找不到就说"误解起源待考证"
不要编造起源,不确定就诚实说明。
```

#### Agent 6:延伸Agent
**职责**:生成"你可能还想知道"的相关内容
```
你是冷知识推荐官。
当前问题:{用户输入} 当前答案:{回答}
推荐3个相关的、有趣的冷知识问题(疑问句),角度新颖能勾起好奇心。
```

#### Agent 7:溯源Agent
**职责**:标注真相的信息来源
```
你是信息溯源员。
资料:{检索结果}
标注来源:来源类型(维基/论文/科普网站)+ 名称/链接。来源不明确则标"来源待考证"。
```

#### Agent 8:审查Agent(灵魂,防幻觉)
**职责**:交叉验证,标注置信度
```
你是质量审查员,防止AI编造。
用户问题:{用户输入} 答案:{回答} 来源:{溯源结果}
判断置信度:🟢确证(有权威来源) / 🟡趣味参考(有来源但非权威) / 🔴存疑(无可靠来源,改为"暂时没找到可靠资料")
输出:置信度等级 + 是否需修改答案。
```

### 5.3 冷知识 vs 辟谣的Agent调度

```
Orchestrator判断问题类型:

冷知识问题("章鱼有几个心脏"):
  检索 → 翻译 → 科普 → 溯源 → 延伸 → 审查

误解辟谣("鱼记忆只有7秒"):
  检索 → 翻译 → 辟谣 → 误解溯源 → 溯源 → 延伸 → 审查
              ↑多了辟谣和误解溯源两个Agent
```

### 5.4 面试讲法
> "我把任务拆成8个Agent各司其职,还根据问题类型动态调度——冷知识走科普链路,误解辟谣走辟谣+误解溯源链路。最有特色的是误解溯源Agent:不只告诉用户'这是假的',还追溯误解从哪来、为什么流传。这比单纯辟谣更有价值,能帮用户建立批判思维。同时审查Agent做质量兜底,没依据的标存疑不瞎编。"

## 六、辟谣回答结构(双重溯源)★★★

### 6.1 完整辟谣回答示例

用户问:"鱼的记忆只有7秒?"

```
┌────────────────────────────────┐
│ 🔴 真的假的?→ 假的!            │
├────────────────────────────────┤
│ ✅ 真相:鱼的记忆可达数月        │
│    依据:研究证明金鱼能记住3个月 │
│    前的训练 [来源:维基百科]      │
├────────────────────────────────┤
│ 🕵️ 误解从哪来:                  │
│    可能源于早期都市传说,被影视  │
│    作品(如《海底总动员》)强化   │
│    [误解来源:待考证]             │
├────────────────────────────────┤
│ 💡 为什么会误传:                │
│    人倾向相信简单有趣的说法      │
├────────────────────────────────┤
│ 🤔 你可能还想知道:              │
│    · 金鱼真的会认主人吗?        │
│    · 哪些动物记忆力最强?        │
└────────────────────────────────┘
```

### 6.2 误解溯源的诚实原则
```
✅ 起源明确的误解 → 标注来源("来自某影视作品")
🔶 起源模糊的 → "起源待考证,可能源于..."
❌ 完全查不到 → "误解起源不明"
```
> 不编造误解起源,查不到就诚实说明。这是辟谣产品的底线。

## 七、防幻觉设计(核心竞争力)

### 7.1 三级置信度机制

| 等级 | 条件 | 展示方式 |
|------|------|---------|
| 🟢 确证 | 有权威来源(维基/论文) | 正常回答 + 来源链接 |
| 🟡 趣味参考 | 有来源但非权威 | 回答 + "趣味参考,建议核实" |
| 🔴 存疑 | 无可靠来源 | "这个问题暂时没找到可靠资料" |

### 7.2 防幻觉三道防线
```
防线1:强制引用 —— 没来源的信息不下结论
防线2:置信度标注 —— 让用户知道结论有多可靠
防线3:审查Agent —— 交叉验证,存疑的不强行回答
```

> 设计判断:冷知识产品娱乐属性强,但依然要防幻觉。尤其辟谣——如果把对的当假的辟出去,危害比不辟谣更大。不同的是可信度策略可以分级,用"趣味参考"这种轻松方式处理不确定性。
## 八、核心功能需求

### G-001:冷知识提问
**用户故事**:作为好奇的用户,我希望用大白话问任何冷知识,以便快速得到有趣又靠谱的答案。

| AC ID | 场景 | Given | When | Then |
|-------|------|-------|------|------|

| AC-002 | 联网检索 | 知识库无内容 | 用户问长尾冷知识 | 联网检索后回答+来源 |
| AC-003 | 无法验证 | 检索不到可靠依据 | 用户问无从考证的问题 | 返回"暂无可靠资料",不编造 |
| AC-004 | 英文资料 | 检索到英文来源 | 触发回答 | 翻译Agent翻成中文后回答 |

### G-002:误解辟谣(核心亮点)
**用户故事**:作为想验证常识的用户,我希望知道某个说法是真是假,以便不被误导。

| AC ID | 场景 | Given | When | Then |
|-------|------|-------|------|------|
| AC-005 | 辟谣+溯源 | 用户问一个误解 | 用户问"鱼记忆只有7秒?" | 返回真假判断+真相溯源+误解溯源 |
| AC-006 | 误解起源 | 误解有明确起源 | 触发辟谣 | 标注误解从哪来 |
| AC-007 | 起源待考 | 误解起源模糊 | 触发辟谣 | 诚实说"起源待考证" |

### G-003:今日主题(冷启动)
**用户故事**:作为不知道问什么的用户,我希望首页有当日主题推荐,以便零门槛开始探索。

| AC ID | 场景 | Given | When | Then |
|-------|------|-------|------|------|
| AC-008 | 今日主题 | 用户首次进入 | 打开页面 | 展示当天主题的6-8个冷知识卡片 |
| AC-009 | 点击探索 | 首页有推荐 | 点击某个卡片 | 直接展示该冷知识的完整回答 |

### G-004:你可能还想知道(留存)
**用户故事**:作为探索中的用户,我希望看完一个答案后有相关推荐,以便继续探索。

| AC ID | 场景 | Given | When | Then |
|-------|------|-------|------|------|
| AC-010 | 相关推荐 | 已得到答案 | 回答生成完成 | 展示3个相关冷知识问题 |
| AC-011 | 点击追问 | 有相关推荐 | 点击某个推荐 | 展示该问题的答案 |

## 十一、技术方案

### 11.1 数据源
| 来源 | 用途 | 获取方式 |
|------|------|---------|
| 本地精选知识库 | 高质量冷知识+经典辟谣 | 手动整理50-100条上传Coze |
| 维基百科API | 通用冷知识 | 免费API |
| PubMed | 科学研究(英文) | 免费API + 翻译Agent |
| 联网搜索 | 长尾问题、实时更新 | Coze联网插件 |

### 11.2 实现路径
```
阶段1(MVP):Coze多Agent工作流 + 精选知识库 + 联网插件
阶段2(增强):自建前端(仿灵犀) + 接Coze API
```

### 11.3 隐私说明
- 用户提问不涉及个人隐私(都是公共知识)
- 不存储用户身份信息
- 联网检索经过第三方服务,在隐私说明中告知
